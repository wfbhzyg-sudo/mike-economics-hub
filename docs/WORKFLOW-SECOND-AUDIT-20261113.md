# 第二轮作业全流程审核与改进

日期：2026-11-13。沿用已确认的紧凑纸面、低饱和分区、题目/作答优先和「AI 给分 → 教师复核 → 学生可见」。本轮没有改动原账号、班级、分数和文件的存储关系。

## 结论

上轮修复的是逐题答案保存与手机阅读空间。本轮主要问题集中在 **异常恢复缺少可操作路径** 和 **教师复核时资料定位不准确**。另外，实际操作发现个别学生延时设置的名单接口不存在，导致名单始终为空；这不是视觉问题，已补齐接口及权限限制。

## 本次发现与实际改进

| 影响 | 已确认问题 | 实施结果 |
|---|---|---|
| 高 | 个别学生延时设置调用不存在的学生列表接口，失败被忽略 | 新增教师专用的当前班级学生列表，仅返回 ID、姓名、班级；学生访问被拒绝。加载失败明确提示，不再伪装成空名单 |
| 高 | 多设备修改导入草稿后只能看到“请刷新”；不同版本的本机草稿不能恢复 | 保留当前输入，顶部显示版本冲突；可比较题目、答案、出处、裁切范围及主要布置设置，再选择账户版或明确保留本机版。选择后仍须核对、发布 |
| 高 | 无效限时会被静默改成 0，即不限时 | 服务端拒绝负数、无效数字及超限时长；个别学生截止时间也必须晚于开放时间 |
| 中 | 更换班级后，已有延时规则仍引用原班学生，没有就地提示 | 不删除原规则；显示“不在所选班级”，保留原学生名供核对。发布前定位问题规则，可修改或移除 |
| 中 | 混合作业复核点题号时优先打开题面，教师还要自己找学生照片 | 简答题优先定位本题上传的照片/PDF 或文字；选择题优先题面，旁边保留学生选项。旧作业无逐题关联时明确使用完整作答，不猜照片对应关系 |
| 中 | 原题、其他题图片、学生作答混在一个相册中 | “学生作答 / 本题原题”紧凑切换；相册只包含当前题、当前资料类型的页面。分数输入时不自动换图，切题才切换对应资料 |
| 中 | 学生保存订正后，新编辑框为空，容易以为内容丢了 | 显示最近已保存的答案、说明、附件和时间；页首出现“已保存 N 次订正 · 查看”，可直接定位。新输入区明确叫“继续补充订正” |
| 中 | 后台批阅失败，学生结果页仍说排队等待 | 明确显示批阅中断、作答已保存、无需重复提交；继续检查后台状态，教师重试后可更新 |
| 低 | 订正选项的选中勾号改变了读屏名称，手机按钮触控面积不足 | 选项名称固定，选中通过状态表达；触控目标至少 44×44px |

## 组件与交互安排

### 教师导入和发布

顶部把草稿状态与恢复操作放在同一区域。保存失败保留内容并提供重试；版本冲突需要先比较。比较窗口可暂时关闭，既不自动覆盖账户版本，也不自动发布。当前方案按整份草稿选择，不做不可靠的自动逐字段合并。

班级仍使用横向多选，个别学生规则按需展开。名单只含当前教师有权管理的学生；切换布置班级后，原规则仍可见，但不允许带着无效规则发布。提示与出错规则相邻，减少教师在长表单中查找问题。

### 教师复核

主空间继续给原件。资料切换位于大图上方，不新增右侧说明卡片，不显示评分标准。紧凑的 indicative score 保持原有位置。手机只展开当前题得分，全部分数按需展开。

点题号选择对应资料；在同一道题中改分、恢复 AI 初评分不会改变当前正在看的图。题面与学生照片分别记住浏览位置。旧版共同附件没有确定的题号对应关系时，继续显示完整作答，避免错误地把第 N 张照片当第 N 题。

### 学生订正与异常状态

已保存订正使用低饱和绿色区块，显示真实记录；新输入框只承担补充内容。保存后原成绩保留，订正次数与历史记录可回看。

批阅中断与排队分开表达。学生知道作答已在服务器保存，无需反复交卷；教师继续通过已有重试、复核和发布流程处理。错误提示不把内部服务诊断直接展示给学生。

## 全流程审核覆盖

| 环节 | 本轮核对内容 |
|---|---|
| 登录与班级 | 沿用统一账号；教师学生列表限制在所属班级；学生不能读取教师名单接口 |
| 导入与切题 | 现有跨页、共享图表、答案映射回归继续通过；本轮重点验证草稿保存和多设备冲突，没有重新调用真实模型识别整份 AP PDF |
| 发布 | 未核对题目不能发布；时间限制、截止顺序、个别学生规则检查；返回核对保留草稿 |
| 学生提交 | 既有逐题文字/附件独立、幂等提交、迟交/重交策略回归；合并附件总量及原附件格式校验保留 |
| 后台评分 | 选择题确定性评分，简答使用受控模拟返回验证任务链；失败状态与排队分开 |
| 教师复核 | 图文定位、原题切换、改分和恢复初评分、手机展开全部分数、发布 |
| 成绩与订正 | 4/7 测试成绩发布；选择题 B 与订正说明保存；刷新后仍可看见；原成绩不变 |
| 数据安全 | 本地合成账号和作业；生产发布前加密备份并隔离恢复验证；不删数据库、附件或历史记录 |

## 验证证据

- 主项目自动化 81 项通过；批改 worker 22 项通过。
- 既有隔离全流程集成覆盖 11 项：班级、发布、图片/PDF、重复提交、评分/复核/成绩历史、订正、PDF 导出及补交策略。
- 实际制造另一编辑端更新：账户版答案 D，本机版 B；界面捕获冲突，明确选择本机版后，账户恢复 B 且本机答案出处保留。
- 教师名单接口返回 30 名隔离班级学生；仅返回必要字段；学生请求得到 403。
- 选择学生后取消布置班级：规则仍保留，姓名旁显示不在所选班级；重新勾选后恢复有效。
- 复核第二题直接打开对应学生照片，第三题显示该题文字；切到原题改分后保持原图；恢复初评分后总分仍为 4/7。
- Chrome 1280×900、390×844、768×540 布局检查；768×540 下发布按钮在视窗内，页面没有横向溢出。
- 手机保存订正后，已保存答案、时间和说明直接可见，并能用页首入口定位。
- 生产备份恢复：2 张表、37 行；结构和数据指纹一致，索引与堆检查通过。

以上手机检查是浏览器尺寸模拟，未声称完成实体 iPhone/Android 的相机、软键盘、前后台切换或真实蜂窝弱网测试。本轮模型返回采用受控样本，未重新评估 DeepSeek 实际批改准确率。

## 仍建议继续完善的方向

1. **发布前的风险题列表。** 将跨页、共享图表、缺答案、缺选项集中呈现，优先核对高风险题，避免逐题平均用力。
2. **逐字段草稿合并。** 当前提供明确的整份版本选择；后续可对不同题的独立修改安全合并，对同一道题冲突要求教师确认。
3. **实体手机与长时弱网专项。** 重点验证连续拍摄、多文件上传中切后台、网络切换、键盘遮挡、浏览器存储清理。代码中的恢复路径不能替代这些实测。
4. **旧作业附件人工关联。** 允许教师把历史共同照片标注为对应题号，减少旧作业的反复翻页；在没有关联前继续保留完整原件。
5. **学生学习闭环。** 按已订正/待复习组织下一次复习任务；保持原作业成绩与订正记录分别记录，不把订正完成直接等同于掌握。
