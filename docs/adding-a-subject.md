# 接入一门学科

适用于课程包、题库、作业、模考、错题与学习报告。宏观和微观是两份独立配置。师生继续使用同一套工作台。

## 教研人员准备什么

| 项目 | 示例 | 如何使用 |
| --- | --- | --- |
| 学科 | 名称、简称、英文名、班级名称中使用的别名 | 作业标签、课程导航、班级筛选共用 |
| 教学目录 | Unit 12 → Topic 12.1 | 章节打开位置、资料、题目、错题回看共用 |
| 能力维度 | 第五项技能「分析数据」 | 标记适用的题型，出题包和学情图使用同一编号 |
| 题目 | 原题切片、选项、答案、来源和对应章节 | 完整可靠的选择题可直接计分。缺少可靠答案的题标为待核对 |
| 学习重点 | 各 Topic 的目标、概念、易错点与例题 | 填在单元对应 Topic 的 focus 字段；可先发布已备妥的章节 |
| 开放范围 | 教师、班级、允许学生使用的材料 | 继续使用现有的教学包开放流程 |

## 实施次序

1. 在 `homework/subject-definitions.js` 增加一条配置。学科 ID、已有单元和题目 ID、技能 ID 长期保留。新技能使用下一个正整数，按 ID 对应历史证据。选择蓝、绿、紫、琥珀或灰色之一作为标签色。非 AP 学科省略 `apReference`。无对应互动课本时省略 `bookself`。
2. 按现有题型整理资料。在同级目录中，学科 ID、单元 ID、Topic ID 三者共同定位章节。示例为 `science-unit-12` 和 `12.1`。宏观的 2.1 和微观的 2.1 各自归属独立。优先显式记录学科 ID；沿用通过班名判断学科的旧接口时，把学科名称或登记的别名保留在班名里。
3. 为新增资料准备 JSON 清单。顶层允许 `units`、`questions`、`files`、`topicAdditions`。数组可省略。在历史单元中追加章节使用 `topicAdditions: [{unitId,topic}]`。已有清单需要包含当前使用的 ID 及本批引用的单元、章节、文件、原题元数据。相同题目直接引用已有题目 ID。如需更换既有试题内容，走原有修订流程，保留已发布作业和学生作答的历史快照。
4. 用以下命令检查。第一条自动核对所有学科配置。第二条仅比对资料清单，不连接数据库。碰到重复 ID、跨单元章节、缺失切片、可计分题答案无效会以非零状态退出。清单核验无法判断切片图片中的曲线是否完整、标准答案的学术内容是否准确，入库前需要查看原件。
5. 先在测试环境开放给测试班。教师从题库按 Topic、Skill 选题；学生切换学科、作答、交卷、订正，再查看原题和该学科的技能分布。分别用电脑、手机和未获开放权限的账号验收。正常发布沿用已有 GitHub 和 Railway 流程，数据导入另行完成。

```sh
node scripts/check-curriculum.mjs
node scripts/check-curriculum.mjs incoming.json existing-inventory.json
node --test tests/subject-compatibility.test.mjs
npm test
```

## 参考配置

```js
{
  id: 'science', label: '综合科学', short: '科学', full: '综合科学课程',
  english: 'Science', aliases: [], units: 12, tone: 'purple',
  skills: [
    {id: 1, name: '读图', english: 'Reading graphs', choice: true, practice: '先读坐标轴，再描述变量的关系。'}
  ]
}
```

`units` 是允许的最大单元号。新增学科不需要重新编写课程切换控件和分档标签。已有学科可以继续追加章节和试题。GitHub 推送、拉取请求与 Railway 镜像构建都会执行第三学科兼容测试。为保留老练习，已使用的 ID 不再分配给其他内容。

## 需要单独设计的情况

Bookself 课本、EconQuest 闯关、经济图表和 Mike 的经济学答疑有自己的学科内容。接入这些能力前，需准备相应教材、题型、图表或答疑规则。实验操作评分、音频口语评分等新评价方式也需额外适配。
