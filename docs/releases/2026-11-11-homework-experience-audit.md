# 学生提交与教师工作台：完整体验复查

2026-11-11。基于原线上版本 `421cd7732222cd4adcf8a92264d4e2e9392a9925`，保留当前低饱和度配色、图片优先的批阅台、Bookself 账号和原网址。

## 审核范围

学生：作业列表、PDF 阅读与定位、照片/PDF/文字作答、上传失败恢复、草稿、正式提交、提交凭证、成绩、原作答、错题订正、账户。

教师：总览、班级与学生、题库、游戏与补练、反馈、设置记录、作业管理、班级提交名单、新建/编辑、参考答案、逐题评分点、成绩档案、图片优先的 indicative score 复核。

## 已实施的改进

| 发现 | 改动与使用结果 |
| --- | --- |
| 上传完成后，状态文字可能停留在“正在上传” | 每次绘制重新计算状态；显示已添加页数。上传中、失败、完成互不混淆。 |
| 移除附件没有即时恢复入口 | 增加“撤销”，仅恢复本次文件关联，不删除原始文件。继续添加新文件后结束该次撤销。 |
| HEIC 等格式的恢复路径不清楚 | 上传前说明支持格式；失败文件单独列出，已上传附件保留，可重试或不添加。 |
| 确认清晰完整后再修改作答，确认仍有效 | 附件和文字改变后重置确认，最后提交前再次核对。 |
| 长表单的错误难以发现，折叠内容可能藏住错误 | 统一顶部错误汇总及字段旁提示；点击提示展开对应区域，滚动并聚焦到具体字段，填写内容保留。 |
| 参考答案长表单阻碍快速定位题号 | 多题默认折叠；题号、每题分值、总题数和总分始终可扫读。支持展开/收起全部。手机已有评分点时折叠源答案。 |
| 新增题目的修改状态不完整 | 新增、删除和评分点操作显式标记未保存；返回题纸会保存完整草稿。10 题原样保存验证通过。 |
| 手机成绩页先显示一大段学生名单 | 改为学生选择框及上一位/下一位；保留姓名/账号搜索，成绩档案紧接着显示。桌面继续保留名单与档案并列。 |
| 教师班级、题库和学生错题搜索缺少可见定位 | 安全高亮命中内容；错题搜索忽略大小写，并显示命中的题目/知识点上下文。PDF 原文定位保留。 |
| 学生不易区分草稿和正式提交 | 保存提示明确“草稿、尚未提交”；正式提交后固定显示时间、附件页数/文字作答和提交编号，刷新仍可核对。 |
| 教师总览和其他列表统计口径可能不一致 | 使用同一套有效提交聚合，按学生和作业取最新提交；草稿不计正式提交，旧成绩等待新结果期间继续保留。 |
| 不同功能切换后仍留着隐藏的旧表单 | 卸载时清理旧内容，避免重复搜索框标识干扰定位；返回时关闭旧预览，避免不可见弹层阻挡操作。 |
| 手机菜单关闭后焦点可能丢失 | 显式保留触发按钮焦点；异步加载不再夺走用户正在操作的焦点。 |
| 手机小按钮、文字尺寸与页面语义不统一 | 提高返回、品牌和折叠开关的触摸区域；教学范围选择框使用 16px，补全主内容区域和对话框名称，导航改为统一线性图标。 |

发布成绩、复核评分点和参考答案依旧是独立权限与动作。本次没有增加 AI 判分解释，也没有更换模型、改评分逻辑或改动真实分数。

## 参考依据及采用方式

- [Google Classroom：提交作业](https://support.google.com/edu/classroom/answer/6020285?hl=en)：附件与正式提交分开处理，提交状态明确可查。采用流程层次，不照搬其截止与重交政策。
- [Canvas：核对学生提交](https://community.instructure.com/en/kb/articles/662698-verifying-student-submissions)：文件存在与正式交付不是同一状态；保留持久的时间与提交凭证。
- [GOV.UK：错误汇总](https://design-system.service.gov.uk/components/error-summary/)及 [GOV.UK Frontend](https://github.com/alphagov/govuk-frontend)：摘要链接到具体字段，错误信息靠近输入，保留已填内容。
- [Carbon：数据表格](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines)及 [Carbon GitHub](https://github.com/carbon-design-system/carbon)：搜索、筛选、主要动作集中于任务上下文，按需展开细节，不添加装饰性仪表盘。
- [W3C：焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)及 [对话框交互](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：错误定位可见、弹层可关闭、返回焦点有明确位置。

未引入 UI 框架、第三方运行时或新图片。以上规范转译为当前产品的轻量实现；不为追求模板外观更换现有导航、数据模型与产品身份。

## 验证与保全

- 独立临时数据库、34 个模拟账号；真实照片/PDF 上传与原件下载、文字提交、草稿刷新恢复、重交、权限和分数保留。
- 42 项自动测试；19 组桌面/触屏阅读与作业流程回归；9 组本轮体验流程；10 题折叠与返回保存、菜单焦点、预览后返回另有 Chrome/WebKit 验证。
- 16 个主要页面在 320、390、1440px 检查布局和自动可访问性；另覆盖平板、短横屏、减少动态效果、PDF 缩放/旋转/高亮、弹层定位。
- 图片优先的复核台验证缩放、PDF 翻页和手机紧凑分数栏；不修改或发布真实学生分数。
- 生产数据先加密备份，在独立临时数据库恢复，结构、内容、角色和索引检查通过。发布前后比较作业、提交、附件、参考答案版本等业务记录指纹。
- 发布仅更新原 GitHub 项目代码及现有 Railway 服务；不删除项目、数据库、卷、附件，也不迁移网址。

浏览器触屏模拟和 WebKit 不是实体 iPhone/Android 测试。软键盘、浏览器地址栏收缩和真实手指体验仍需真机复核；自动检查通过也不等于完整 WCAG 合规认证。

设计检测已运行一次：颜色/圆角/字号提示主要来自旧规范与当前批准页面的差异；旧深蓝背景光晕提示在最终浅色页面已被覆盖。设计规范附属存档落后于页面现状，本轮未擅自重写该存档。实际变更以本记录和渲染验收为准。
