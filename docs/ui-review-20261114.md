# Teacher and student UI review — 2026-11-14

This is an incremental Operate / Read refinement of the existing ivory, navy and muted semantic-color system. Keep original course materials, grading behavior and the compact indicative-score review. Do not restore a rubric or generated explanation panel.

## Component decisions

| Component | Current behavior | Reason |
|---|---|---|
| Correction reference | MCQ uses the submitted choice for the current question. A missing key in an explicit choice map means unanswered. Written answers use explicitly linked question files/text; legacy submissions retain their complete answer. Text-only references use natural height and no image toolbar. | Let students compare their old answer with the correction without searching unrelated pages. |
| Scheduled assignment | Before opensAt, missing rows and counts use neutral “待开始”; opened work retains the existing submitted/missing colors. Prior submissions and grades stay accessible. | Future work must not look like an overdue intervention. |
| Student slide reader | “专注阅读” and “退出专注”. Teacher uses “开始授课”; all exits reset its label. | The action describes each role's task and current state. |
| Page text | More → “查看本页文字” extracts the current original PDF page on demand. “查看原页” restores the existing reader and annotation tools. Paging remains shared. No AI generation. | A readable, selectable text alternative without adding permanent toolbar clutter. Scanned pages explicitly report absent extractable text; automatic text does not describe graphs or guarantee PDF reading order. |
| Text annotation | Keyboard activation of T opens an editor at a default page position; Enter/Space on the text-mode canvas also creates a note. Escape closes the editor first. | The text feature must work without a pointer. Pointer placement remains available. |
| Library navigation | Repeated keyboard next-question activation keeps the current action focused; active lesson tabs retain focus across route rendering, including pack aliases. Modal close restores the visible menu trigger. | Users should not restart navigation after each step. |
| Small-screen course layout | Teacher course content reserves fixed bottom navigation and safe-area clearance. | Final lesson lines remain reachable at the maximum scroll position. |

## Validation standard

Check teacher and student roles independently at real measured desktop and narrow browser viewport sizes. Inspect keyboard transitions, menu return focus, extracted text, next-page updates, text-note save/reload, source-image fallback and plain-text corrections. These are browser viewport simulations; physical touch, stylus, mobile keyboard and screen readers require separate device validation.

The applicable interaction references are [W3C modal-dialog focus guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [WCAG 2.2 focus not obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum), and [WCAG keyboard operation](https://www.w3.org/WAI/WCAG22/Understanding/keyboard).

Production data and source files are outside the change scope. The release must preserve the existing URLs and verify original record fingerprints after deployment.
